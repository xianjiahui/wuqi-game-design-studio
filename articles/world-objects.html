01

一个资源点通常包含多个对象

玩家看见一处资源点，可能先操作入口，经历采集过程，再从结果容器领取产物。入口、过程装置和终局容器拥有不同能力，可能需要不同的对象实例。策划应先写完整流程，再判断需要哪些对象，不能因为美术看起来是一处场景就把所有状态塞进一行。

发现资源点 → 满足交互条件 → 执行采集过程
→ 生成或开放结果 → 领取 → 耗尽与刷新

本篇采用虚构的矿脉家族说明维护方法：普通矿脉、富集矿脉与任务矿脉共享部分表现，但产出、开放条件和刷新规则可能不同。所有名称与差量均为教学示例。

02

把五种身份放在正确的位置

层级保存什么矿脉示例
对象原型稳定身份与能力组合引用普通矿脉这一类可生成对象
表现模板模型、名称、地图与血条等表现共用岩壁模型与交互名称样式
业务能力采集、容器、条件等专门参数采集要求与结果容器
生命周期生成、耗尽、死亡或刷新规则采完后等待刷新
场景实例一次实际存在的对象及其状态某区域坐标上的这处矿脉

表现模板复用不意味着业务相同。任务矿脉可以沿用普通模型，却只允许相关任务状态交互。反过来，同一业务能力也可以挂在不同外观上。对象原型负责装配这些引用，实例负责记录本次发生了什么。

实例身份不能用模型名代替。同种矿脉在两个位置同时存在，需要独立保存已采集进度、占用或产物状态；修改某一个实例的朝向，也不能反向改掉全部共享模型。

03

家族给出共同合同，变体只表达差异

配置项家族基线富集变体任务变体
表现岩壁与矿石外观增加可识别的富集表现按任务需要增加标识
业务能力采集后开放结果沿用采集结构，替换产出方案增加任务资格
生命周期采用普通刷新策略使用自己的刷新策略服从任务状态
交互统一操作方式保留同一基本操作补充资格不足原因
实例状态独立记录每处进度仍逐实例记录关联任务所属上下文

家族是维护方法，不必要求运行时一定支持面向对象继承。可以在编辑工具中维护基线与差量，导出时展开为现有格式。重要的是保留差异来自哪里，并能查看继承后的完整结果。

覆盖语义必须明确：未填写表示继承，显式零表示真正的零，清空引用则用明确操作表达。若空白同时代表继承、禁用和忘填，批量生成后就无法稳定解释结果。

04

能力组合必须形成完整链路

资源点配置了采集组件，还需要交互检测、动作按钮、状态反馈与结果去向。若采集结束生成容器，必须能找到容器原型及其库存规则；若直接给予资产，就不能再生成一份可领取结果。

连接要检查的问题
原型到能力声明的能力组合是否合法，必要参数是否齐全
能力到交互注册类型能否找到检测与按钮定义
采集到结果结果只生成一次，归属与接收位置明确
结果到生命周期领取后是否耗尽，何时允许刷新
实例到权威状态保存和同步的状态与客户端表现一致

美术资源可加载、配置引用存在，都只是其中一部分。完整纵向样本需要让玩家发现、操作、得到结果，再看到正确的耗尽与恢复。先跑通一个家族样本，再扩展变体，才能知道批量复制的究竟是不是完整结构。

05

修改共享模板前先做影响查询

假设普通与富集矿脉都引用同一交互表现模板。为了突出富集矿脉，直接修改共享模板的名称样式，会同时改变普通矿脉。正确决策取决于目标范围：若全家族都要改善可读性，修改共享模板；若仅富集需要区别，建立新版本或专用模板并迁移对应引用。

拟修改字段 → 所属模板 → 直接引用原型
→ 各家族与变体 → 场景生成来源 → 受影响实例规则

审查结果应列出受影响对象及其差异，而不只是引用总数。任务专用变体可能和普通资源点共用外观，却对文字、交互窗口有特殊要求。数量很少的例外也值得单独检查。

对生命周期或业务模板的修改，还要决定已有实例是否继续旧规则、立即迁移还是等下一次生成生效。静态配置变更不能自行回答在线实例如何处理，这项决定需要写进发布合同。

06

批量生产从规范输入开始

  1. 定义家族合同与允许的能力组合，选定已有模板。
  2. 列出真正需要的变体，每个差量说明设计原因。
  3. 展开完整配置，记录家族、变体与生成批次，校验主键和引用。
  4. 选择一个完整纵向样本，检查交互、产出、耗尽与刷新。
  5. 批量生成其他对象，重点审查异常差量和高引用模板。
  6. 保存基线、差量与可回退版本，保证下一次修改能够追溯。

自动校验至少包含身份唯一、外键存在、能力组合合法、交互链闭合、必填值与范围正确。同一家族只有一条记录改变检测角度或图标时，可以提示人工确认，但不能自动改回：它也可能是有意设计的变体。

未被引用的记录只能先进入清理候选。生成层、任务或运行时引用可能不在同一张表里，不能只凭一个局部查询就删除。

07

用维护成本检验结构

可以用三个任务评审架构：新增一个只换外观的资源点，新增一个产出不同的变体，调整全家族的共同交互表现。每个任务都应有明确的最小修改范围，不需要在大量复制行里逐个搜索同一个参数。

再检查修改后的可解释性：策划能否看见某变体的完整结果、哪些字段继承、哪些字段覆盖；程序能否追到最终数据来源；验收能否找到代表实例。只减少行数却隐藏了继承关系，仍会增加后续理解成本。

规模化配置的核心是稳定身份、明确职责和可审查的差异。世界对象数量可以增长，但每次变化的影响应始终可以说清楚。
